# Stock Research Copilot 开发计划

> 依据 `README.md` 的定位，这个项目先做成一个面向股票研究场景的 **Java + Spring Boot + RAG + Agent** 工具。
>
> 这份计划按**后端 / 前端 / 基础设施 / 联调**拆开，直接落到每一步怎么做、先做什么、哪些可以并行。

---

## 1. 这版项目先交付什么

先不追求“大而全”，先把最核心的研究链路跑通：

1. 能上传财报 / 公告 / 研报。
2. 能把文档解析、切分、入库。
3. 能按公司做检索问答，并返回引用来源。
4. 能生成结构化研究摘要。
5. 能把 Agent 的工具调用跑起来。

这五件事做完，项目就已经有明确的演示价值和继续扩展的基础。

---

## 2. 开发方式

### 2.1 分工方式

- **后端**：文档接入、解析、切分、检索、RAG、Agent、接口定义。
- **前端**：文档管理、问答页面、摘要页面、结果展示。
- **基础设施**：MySQL、Redis、向量库、模型配置、部署脚本。
- **联调**：前后端接口对齐、链路跑通、问题修复。

### 2.2 并行标记

- `【可并行】` 表示这个步骤可以和别的步骤一起做。
- `【依赖前置】` 表示必须先完成前面的步骤。
- `【联调点】` 表示这个步骤需要前后端一起确认接口或流程。

---

## 3. 总体推进顺序

按下面的顺序推进，不绕路：

1. 先定范围和技术方案。
2. 再把后端、前端、数据库基础工程搭起来。
3. 接着做文档入库链路。
4. 然后做 RAG 问答主链路。
5. 再做研究摘要和 Agent。
6. 最后补前端体验、测试、性能和扩展能力。

## 7. 这版计划的判断标准

我会用下面几条来判断这版开发是不是走对了：

- 文档能不能稳定入库。
- 问答能不能给出有来源的答案。
- 摘要能不能按研究场景输出。
- Agent 能不能真正调用工具，而不是只做文字包装。
- 前端能不能把结果、来源、历史记录讲清楚。

如果这些都成立，这个项目就不是“一个演示型 AI 项目”，而是一个真正能继续迭代的股票研究工具。
